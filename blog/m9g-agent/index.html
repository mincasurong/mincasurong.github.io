Building a Multi-Agent Coding Harness from Scratch and Why It Failed: Inside m9g-agent-corps vs. OmO, OpenCode, Claude Code, and Antigravity

We built m9g-agent-corps, a 28-module Python coding harness in src/ag_harness/ with 169 passing unit tests. On daily multi-file tasks, it lost on speed and reliability to Oh-My-OpenAgent, OpenCode, Claude Code, and Google Antigravity. Six inner-loop flaws caused that failure, including unwired edit hooks, regex status parsing, and 300-second buffered subprocesses. We retired the outer loop and extracted seven stateless tools into m9g-mcp.

Why we tried to build a standalone multi-agent coding harness

During a 1-billion-token weekend engineering sprint on gemini-4-carbon and gemini-3.8-flash, three failure modes kept recurring in standard LLM coding sessions. Reading full source files into the frontier prompt bloated context windows. Line-number drift across sequential edits corrupted files. Failed edits polluted the user's staged .git/index and forced manual cleanup.

We bet that a custom three-tier harness named m9g-agent-corps (CLI aliases m9g-code and m9g) could fix all three problems at once. In our design, a Tier-1 Higher Brain (APEX: gemini-4-carbon and gemini-2.5-pro) held cross-file architecture in cached memory while dispatching file-level edits to isolated Tier-2 (MIDDLE: gemini-2.5-pro-preview) and Tier-3 (WORKHORSE/SCOUT: gemini-3.8-flash and gemini-3.5-flash-lite) workers. Across several weeks, we wrote 28 Python modules (~640 KB) in src/ag_harness/ and 17 test suites with 169 passing unit and integration tests.

What we built across 28 modules and 169 passing unit tests

D:\git\m9g-agent-corps was not a thin prompt wrapper. We built concrete implementations for all eight components codified in HARNESS2_8_COMPONENTS (argon_omo_substrate.py:617: c1: system_prompt, c2: context_policy, c3: long_term_memory, c4: tool_guidance, c5: sub_agents, c6: skills_and_guardrails, c7: scripts, c8: hooks_and_plugins):

Investigation 01 • Token & Cache Economics

Immutable Prefix Caching & Tail-Only Dynamic Injection

ImmutablePrefixBuilder (argon_omo_substrate.py:766) and corps.jsonc preserve Gemini 2.5 Pro and Gemini 4 Carbon's 95% implicit cache discount ($0.10/1M cached vs. $2.00/1M uncached). The builder strips dynamic timestamps (Generated:, Timestamp:, Current git status:) from message index 0, locks <immutable_system_prompt>, <immutable_agents_md>, sorted <immutable_tool_schemas>, and <immutable_repo_map> under a verified SHA-256 prefix_hash, caps static prefix text at 28,000 characters, and appends turn-varying state (<memory_sidecar_constraints>, <intent_gate_status>) only at the user message tail.

Investigation 02 • Drift-Tolerant Code Mutation

SHA-256 Hashline Editing & AST Skeletonization

In hashline_tools.py (508 lines), HashlineEditor.hashline_read() prefixes every line with a 4-character SHA-256 content hash (L{n}:{hash}|) and loads parent-directory AGENTS.md files once per session via _SURFACED_DIR_AGENTS. hashline_edit() relocates drifted spans inside a ±25-line window (_locate_matching_span), applies hunks bottom-up (reverse=True) so line indices never shift mid-batch, and runs Python compile() AST validation in under 1 ms. In context_controller.py, skeletonize_python_code() reduces Python files to signatures and docstrings, cutting token count by 75% to 90%.

Investigation 03 • Atomic Workspace State

Shadow GIT_INDEX_FILE Checkpoints & SQLite WAL Store

In checkpoint.py (685 lines), WorkspaceCheckpointManager._capture_git_tree_sha() snapshots dirty worktrees and untracked files without touching the user's staged .git/index. It copies .git/index into a tempfile.TemporaryDirectory, sets GIT_INDEX_FILE, runs git add -A and git write-tree to record a 40-character tree SHA, and restores state via git read-tree plus git checkout-index -a -f with a 250-file Copy-on-Write fallback. In session_store.py (1,508 lines), a thread-locked SQLite WAL state machine logs turn transitions from CREATED through STREAMING and TOOL_PENDING to COMMITTED or ROLLED_BACK.

Investigation 04 • Self-Healing & Continual Memory

5-Tier Hook Pipeline, IntentGate & Git Fault Sidecar

In argon_omo_substrate.py, FiveTierHookPipeline coordinates five stages: Tier 1 loads past fault rules from GitMemoryFaultSidecar (an isolated Git repo at .m9g/fault_memory); Tier 2 (IntentGate) classifies prompts into information, judgment, plan, or build and blocks mutating tools until prove_plan() runs; Tier 3 runs repair_json_arguments() on malformed tool JSON and verifies hashline spans; Tier 4 trims tracebacks via extract_concise_stack_trace(); and Tier 5 commits resolved faults as YAML-frontmatter lessons (cue, lesson, evidence).

Investigation 05 • Multi-Wave Orchestration

11-Agent Roster, 16 Categories, DAGEngine & Boulder

Modeled after OmO's specialist roles, gemini_roster.py (649 lines) defines 11 agents (sisyphus, oracle, metis, momus, hephaestus, flash-worker, qa-executor, explore, librarian, code-reviewer, gate-reviewer) across 16 task categories. ulw_engine.py pairs TodoManager with persistent BoulderEngine continuation state, and dag_engine.py (450 lines) runs Kahn's topological wave sort with CyclicDependencyError detection, bounded semaphore concurrency, and upstream handoff injection.

Investigation 06 • Cross-OS & Mobile Control

WSL2 Bridge, GF(2⁸) Terminal QR PWA & System Doctor

In wsl_bridge.py (442 lines), WSLPathTranslator converts Windows and WSL2 paths in both directions, forwards credentials via WSLENV, and reaps POSIX process groups cleanly. In remote_control.py (849 lines), pure-Python Galois Field GF(2^8) Reed-Solomon QR encoding renders pairing codes in Unicode half-blocks (▀▄█) for mobile control, paired with herdr_bridge.py IPC reporting and run_system_doctor() in doctor.py.

Six kernel mistakes that broke our standalone harness in daily work

All 169 unit tests across 17 test files passed. Yet on real multi-file refactors and bug fixes, m9g-agent-corps ran slower and broke more often than OmO, OpenCode, Claude Code, and Antigravity. Auditing our own call graph exposed a hard systems truth: unit-tested helper modules do not make a reliable coding harness when the inner execution loop is loosely coupled. Six specific kernel mistakes caused the failure:

Failure Cause 1: Leaving argon_omo_substrate.py unwired from main.py and agy_workers.py

We implemented FiveTierHookPipeline, IntentGate, HashlineEditor, ImmutablePrefixBuilder, and TmuxSubscriptionWatcher inside argon_omo_substrate.py (1,245 lines) and tested them in run_argon_smoke_benchmarks(). Yet the live REPL loop (stream_turn() in main.py:124) and worker launcher (spawn_agy_worker() in agy_workers.py:427) instantiated google.antigravity.Agent(config=config) directly. Its built-in runtime tools (edit_file, replace_file_content, run_command) bypassed FiveTierHookPipeline, IntentGate, and HashlineEditor on every call. Our prompts asked workers in English prose to check their edits, whereas OmO, OpenCode, and Claude Code enforce edit validation, permission checks, and diagnostics inside the single mandatory tool-dispatch function.

Failure Cause 2: Regex status parser defaulting truncated turns to SUCCESS (agy_workers.py:296-305)

When the Tier-1 Higher Brain delegated work to a Tier-2 or Tier-3 subagent, WorkerHandoffReport.parse_from_markdown() never received a typed execution result. Instead, it asked the worker to print a Markdown footer and scraped that text with a regular expression:

Source Post-Mortem: src/ag_harness/agy_workers.py (Lines 296 to 305) Ref: M9G-TR-2026-02
status_match = re.search(r"#{1,4}\s*STATUS:\s*([A-Za-z_]+)", raw_text, re.IGNORECASE)
if status_match: status = status_match.group(1).upper()
elif not raw_text.strip() or raw_text.lstrip().startswith(("[Worker Execution Error", "Traceback")): status = "FAILED"
else: status = "SUCCESS"

How this corrupted multi-wave DAGs: Whenever a worker hit its output token limit, truncated mid-sentence, exited a CLI subprocess with a non-zero return code (check=False at line 415), or answered without a ## STATUS: heading, parse_from_markdown() returned status = "SUCCESS" with files_modified=[]. DAGEngine marked the failed wave complete and scheduled downstream waves onto an unedited worktree.

Failure Cause 3: 300-second buffered subprocess.run black boxes (agy_workers.py:409-424)

To invoke external CLI workers (agy.exe -p or omo.exe -p), spawn_agy_worker() called a blocking subprocess.run inside asyncio.to_thread:

Source Post-Mortem: src/ag_harness/agy_workers.py (Lines 409 to 417) Ref: M9G-TR-2026-02
proc = await asyncio.to_thread(
  subprocess.run, cmd, cwd=abs_ws, capture_output=True, text=True, timeout=300, check=False
)

Why buffered subprocesses lose to live kernels: Setting capture_output=True hid all stdout and stderr for up to five minutes. The orchestrator could not tail live progress (unlike OmO's task_output(mode="tail") or monitor), could not steer a drifting worker mid-turn (unlike OmO's task_send or bash_input), and threw away every intermediate diagnostic if subprocess.TimeoutExpired fired at 300 seconds.

Failure Cause 4: Rule-1 mandatory delegation tax and 19-tool prompt bloat (config.py:381-485)

In config.py:457, Rule 1 forbade the Higher Brain from reading 500-line files directly and forced it to call spawn_agy_worker() for every multi-file edit, UI build, reverse-engineering pass, or test run. At the same time, _resolve_agent_tools() bound 19 Higher-Brain tools and up to 28,000 characters of static prompt prefix on Turn 1.

Why this tripled latency on 1-to-3 file edits: On a three-file bug fix, Claude Code, OpenCode, and OmO read the target spans, apply exact edits, and run diagnostics inside one process in 24 to 34 seconds. Rule 1 forced a cold-start relay: the Higher Brain spawned a fresh worker process, the worker re-read files from disk and compressed its findings into a 300-word Markdown summary, and the Higher Brain tried to debug failing tests after that summary had stripped the exact cross-file type signatures it needed.

Failure Cause 5: Destructive middle-out string slicing (hooks.py:23-25 and subagents.py:34)

To cap token-per-minute burn, cap_tool_output() truncated any tool output longer than 12,000 characters by keeping the first 4,000 characters and the last 8,000 characters, while trim_context_for_tier2() cut the center out of file_context:

Source Post-Mortem: src/ag_harness/hooks.py (Lines 23 to 25) & subagents.py (Lines 35 to 40) Ref: M9G-TR-2026-02
DEFAULT_MAX_TOOL_CHARS = 12000  |  HEAD_CHARS = 4000, TAIL_CHARS = 8000
file_context[:keep_chars // 2] + "\n...[TRIMMED]...\n" + file_context[-(keep_chars // 2):]

Why middle-out slicing triggers hallucinated code: In a 600-line Python module or a multi-failure pytest log, cap_tool_output() deletes lines 120 to 380 right out of the middle. Blind to those deleted definitions, workers invented function bodies or looped on repeated file reads. OmO, OpenCode, and Claude Code never delete the middle of a file read; they paginate with explicit line offset and limit parameters so the model always sees contiguous line numbers.

Failure Cause 6: Hard-kill loop breaking and nested orchestrator overhead (agy_workers.py:557)

When StreamLoopMonitor saw three identical tool calls, _run_worker() executed break on the response stream and aborted the worker with STATUS: FAILED, discarding its entire working context. Worse, when m9g-agent-corps spawned agy or omo as a CLI worker without disabling inner delegation, it stacked one multi-agent orchestrator on top of another, paying double system-prompt overhead (142 s median latency on a 3-file refactor). By contrast, OmO injects in-stream TTSR (<system-interrupt>) nudges that redirect a stuck model without killing its session.

Why extracting seven stateless tools into m9g-mcp worked

The post-mortem left one clear conclusion: building a competing outer agent loop wastes effort when OmO, OpenCode, Claude Code, and Antigravity already run tight in-process tool loops, live PTY terminals, and typed error recovery. At the same time, seven stateless modules from src/ag_harness/ solved concrete gaps that those harnesses still encounter on large repositories: 75% to 90% AST token compression, shadow Git index checkpoints that leave staged files untouched, and SHA-256 line-hash batch edits.

In commit cfa9395 (ag_harness/agy_mcp_server.py, 662 lines), we retired the outer orchestrator and shipped those modules as m9g-mcp (m9g-power-tools), a stateless JSON-RPC 2.0 stdio MCP server installed via m9g --install-agy-mcp -w .. Because each tool takes explicit inputs and returns a deterministic JSON payload inside the host harness's own validated tool loop, OmO, OpenCode, Claude Code, and Antigravity gain all seven capabilities with zero extra delegation hops:

  1. m9g_skeletonize (context_controller.py): Parses Python ASTs into function signatures and docstrings, cutting file read tokens by 75% to 90% before full-span inspection.
  2. m9g_checkpoint (checkpoint.py): Creates, diffs, and restores workspace snapshots (create, list, diff, undo, rollback) through a temporary GIT_INDEX_FILE (git write-tree and git read-tree) without modifying the user's staged .git/index.
  3. m9g_hashline_read (hashline_tools.py): Reads explicit line ranges with 4-character SHA-256 content hashes (L{n}:{hash}|) and loads subdirectory AGENTS.md rules once per session.
  4. m9g_hashline_edit (hashline_tools.py): Applies bottom-up, hash-verified multi-file edits with ±25-line drift relocation and sub-millisecond Python compile() syntax checks.
  5. m9g_code_intel (hashline_tools.py): Runs structural symbol search (ast_grep), definition lookup, reference lookup, document symbol listing, and docstring hover across Python, TypeScript, JavaScript, Rust, and Go.
  6. m9g_memory (memory_store.py): Stores and updates YAML-frontmatter Markdown memory blocks (decisions, architecture, learnings) with automatic wikilink updates.
  7. m9g_gemini_media (gemini_api_cli_bridge.py): Generates speech, images, and video clips (tts, image, video) directly to output_path on disk so binary base64 blobs never enter the model context window.
