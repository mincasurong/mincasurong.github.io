Project STAMP: Deterministic Verification Gates and Closed-Loop Context Repair for Multi-Arm VLA Task and Motion Planning

Allowing a Vision-Language-Action (VLA) planner to stream unverified Cartesian poses or joint commands directly to low-level robotic controllers exposes multi-manipulator workcells to unreachable inverse-kinematics targets, 3D workspace collisions, joint torque spikes, and concurrent zone mutex deadlocks. In Project STAMP (v1.0.0-stamp), we decouple high-level multimodal reasoning (Gemini 4 Argon / Gemini 3.5 Flash-Lite) from ROS 2 Jazzy and MoveIt 2 actuation through a strict four-stage closed-loop architecture: Plan (TaskDAG) → Gate (Deterministic Shield) → Execute (MoveIt 2 / ROS 2) → Write-Back (Context Repair). Evaluated across 1,000 multi-arm Franka Emika FR3 episodes in STAMP-Bench-V1 under 60% synthetic fault injection, Project STAMP intercepts 100.0% of unsafe dispatches (610/610) and elevates episode task completion from 39.0% (single-shot VLA) to 100.0% via two-turn geometric and temporal write-back recovery.

Why Direct VLA-to-Controller Execution Fails in Multi-Arm Workcells

When foundation models act as high-level task and motion planners for multi-manipulator cells, a recurring architectural anti-pattern is coupling the model's tool-call output directly to ROS 2 action servers or MoveIt 2 trajectory controllers. Even when a frontier model such as gemini-4-argon correctly decomposes a long-horizon task semantically, single-shot coordinate generation remains vulnerable to four physical failure modes: targets placed outside the manipulator's spherical reach envelope, end-effector bounding boxes that clip workbench obstacles, posture seeds that exceed distal wrist torque limits under payload, and overlapping time windows where two arms contend for the same shared workspace zone or fixture.

Project STAMP (Spatial, Task & Motion Planning, v1.0.0-stamp) resolves this vulnerability by introducing a deterministic verification air-gap between multimodal planning and physical execution. Instead of emitting raw controller commands, the planner is restricted to producing a declarative TaskDAG evaluated against a real-time 3D scene snapshot (SpatialState). No command can reach DecoupledROS2Executor or MoveItPreDispatchGuard unless every node in the directed acyclic graph passes FrankaFR3DeterministicGate with GateVerdict.passed == True.

Project STAMP 4-Stage Closed-Loop Execution Law Ref: M9G-TR-2026-03 (v1.0.0-stamp)
Plan [ GeminiArgonPlanner(Goal, SpatialState, C_repair) → TaskDAG ] → Gate [ FrankaFR3DeterministicGate(TaskDAG, SpatialState) → GateVerdict ] → { PASS: DecoupledROS2Executor(q_sol) | REJECT: FeedbackContextStore.write_limit_back(HardwareFaultLog) → C_repair }

Four Canonical Schema Contracts & Video-to-TaskDAG Ingestion

To guarantee zero ambiguity between the generative planner, the deterministic gate, and external Model Context Protocol (MCP) clients, stamp/stamp_schemas/ codifies four Pydantic v2 models exported as strict JSON Schema Draft 2020-12 artifacts (export_all_json_schemas()):

  • TaskDAG & TaskNode (TaskDAG.schema.json): Represents a parallel multi-arm task graph where each node specifies node_id, assigned manipulator arm_id (FR3_1, FR3_2, FR3_3), primitive action, target_pose [x, y, z, yaw] in world meters/radians, upstream dependencies, claimed shared_zone, required_tool, and scheduled time_window (t_start, t_end).
  • SpatialState (SpatialState.schema.json): Captures the complete 3D workcell state at planning time, including per-arm base transforms and 7-DoF joint states (RobotArmState with joint_torques_nm and custom URDF joint_limits_rad), tracked 3D objects (ObjectPose3D), 3D obstacle AABBs (WorkspaceZoneBox), and active mutex maps (active_zone_locks, active_tool_locks).
  • GateVerdict (GateVerdict.schema.json): Emitted by FrankaFR3DeterministicGate.evaluate_dag(), recording boolean passed, approved_node_ids, rejected_node_ids, pre-solved 7-DoF IK joint vectors joint_solutions (in radians), and cumulative interception_rate.
  • HardwareFaultLog & FaultCode (HardwareFaultLog.schema.json): Standardized diagnostic record binding a rejected node_id and arm_id to a deterministic FaultCode, scalar measured_value vs. limit_value, physical unit, and an actionable correction_hint string serialized via to_context_constraint().

Inside the Four-Layer Deterministic Shield & Closed-Loop Write-Back

Every candidate TaskNode in a proposed TaskDAG is inspected sequentially across four orthogonal physical verification layers inside FrankaFR3DeterministicGate._evaluate_single_node() (and enforced at the controller boundary by MoveItPreDispatchGuard.verify_moveit_goal()). When any invariant is violated, the gate blocks execution and synthesizes a deterministic repair rule for FeedbackContextStore.write_limit_back():

Four-Layer Deterministic Gate Invariants (FrankaFR3DeterministicGate) Ref: M9G-TR-2026-03 • stamp/stamp_gate/__init__.py
1. Kinematic Reach & 7-DoF DLS IK: r_3D = ||p_target − p_base||₂ ∈ [0.15m, 0.85m] ∧ ||FK(DLS_IK(p_local, q_des, q_seed)) − p_local||₂ ≤ 0.015m (15.0 mm)
2. 3D Workspace & AABB Collision: z_target ≥ 0.20m ∧ ||p_xy − p_base,xy||₂ ≥ 0.12m ∧ ∀B ∈ Boxes_obs: AABB(p_target ± [0.04, 0.04, 0.05]m) ∩ B = ∅
3. Joint & Torque Envelopes: ∀j ∈ {1..7}: q_j ∈ [q_min,j, q_max,j] (URDF) ∧ |τ_j| ≤ τ_max,j ([87, 87, 87, 87, 12, 12, 12] Nm)
4. Spatio-Temporal Mutex Locks: ∀(n_a, n_b) claiming shared_zone Z or required_tool T (arm_a ≠ arm_b): max(t_start,a, t_start,b) ≥ min(t_end,a, t_end,b)

FaultCode Enum Deterministic Trigger Condition Injected Context Constraint (write_limit_back) Planner Turn-2 Repair Transformation
IK_UNREACHABLE 3D radial distance r_3D ∉ [0.15m, 0.85m] from assigned arm's fr3_link0 base, or 150-iteration 7-DoF DLS IK residual exceeds 15.0 mm. [STAMP_GATE_FAULT node=... arm=FR3_k code=IK_UNREACHABLE measured=1.98m limit=0.85m]: move target within 0.52m of base Projects target XY radially along the base-to-target vector onto the r = 0.52m kinematic sweet spot and clamps Z ∈ [0.32m, 0.62m].
WORKSPACE_COLLISION Target penetrates table floor (Z < 0.20m), enters the 0.12m base column cylinder, or end-effector AABB intersects an obstacle WorkspaceZoneBox. [STAMP_GATE_FAULT node=... code=WORKSPACE_COLLISION]: End-effector AABB intersects obstacle; raise Z above box.max_z + 0.08m Lifts target Z to max(0.34m, box.max_z + 0.08m), or retracts XY to 0.5 × base_xyz at Z = 0.38m if vertical clearance exceeds 0.68m.
RESOURCE_CONTENTION Two manipulators claim the same shared_zone (e.g., central_table) or required_tool during overlapping [t_start, t_end] windows or active lock. [STAMP_GATE_FAULT node=... code=RESOURCE_CONTENTION]: Shared zone contended over [0.00s, 1.50s]; shift time_window after 1.50s Shifts the contending node's time_window to [mutex_cursor + 0.15s, mutex_cursor + 0.15s + dur] and releases conflicting foreign locks.
JOINT_LIMIT_EXCEEDED Any of the 7 FR3 joint angles violates URDF [q_min, q_max] radians, or joint torque |τ_j| exceeds [87, 87, 87, 87, 12, 12, 12] Nm. [STAMP_GATE_FAULT node=... code=JOINT_LIMIT_EXCEEDED measured=115.0Nm limit=87.0Nm]: retract moment arm & enable reduced_payload_mode Retracts target moment arm to 0.45 × base_xyz at Z = 0.38m, resets seed to FR3_HOME_CONFIG, and sets reduced_payload_mode = True.

Decoupled Deployment: Standalone REST & Model Context Protocol (MCP) Server

A core systems requirement of Project STAMP is that deterministic kinematic and spatial verification should not be locked inside a monolithic simulator process. Through StampStandaloneEngine (stamp/api_server.py), the entire Plan → Gate → Write-Back loop operates as a zero-ROS-dependency microservice over HTTP REST (port :8095) or JSON-RPC 2.0 MCP stdio transport. External agent harnesses can pass custom robot URDF XML definitions (parsed dynamically via parse_urdf_joint_limits()) and reach bounds on every call:

M9G-TR-2026-03 • StampStandaloneEngine REST & JSON-RPC 2.0 MCP Interface Author: Minsu Chang, Ph.D. (M9G)
MCP Tool / HTTP Endpoint Input Contract Deterministic Engine Behavior & Output
stamp_plan_and_verify
POST /v1/stamp/plan_and_verify		 goal, spatial_state, optional urdf_xml, reach_bounds_m, video_events, max_replans Applies custom URDF revolute/prismatic limits, executes closed-loop ClosedLoopStampOrchestrator.run_episode(), and returns verified dag, verdict, and active_write_back_constraints.
stamp_verify_dag
POST /v1/stamp/verify_dag		 Candidate dag (TaskDAG), spatial_state, optional urdf_xml, reach_bounds_m Runs FrankaFR3DeterministicGate.evaluate_dag() in under 2 ms, automatically appends any HardwareFaultLog entries to FeedbackContextStore, and returns GateVerdict with pre-solved 7-DoF joint_solutions.
stamp_write_limit_back
POST /v1/stamp/write_limit_back		 List of HardwareFaultLog objects from simulator or hardware protective stops Serializes hardware faults into deduplicated [STAMP_GATE_FAULT ...] prompt constraints and returns updated fault_summary counts by FaultCode.

Paired with our unattended batch harness (scripts/run_stamp_batch.py), cross-OS WSL2 FastDDS heartbeat watchdog (scripts/fastdds_watchdog.py), and SHA-256 dataset freezer (scripts/freeze_stamp_bench_v1.py), Project STAMP establishes a reproducible blueprint for deploying frontier multimodal models safely across physical multi-arm manipulation stations.
