Project STAMP: Deterministic Verification Gates and Closed-Loop Context Repair for Multi-Arm VLA Task and Motion Planning

Streaming unverified VLA poses to robot controllers causes IK failures, workspace collisions, torque spikes, and zone deadlocks. Project STAMP v1.0.0-stamp inserts a four-stage Plan -> Gate -> Execute -> Write-Back loop between Gemini 4 Carbon and MoveIt 2 on ROS 2 Jazzy. Across 1,000 STAMP-Bench-V1 episodes, FrankaFR3DeterministicGate blocks all 610 injected fault episodes in under 2 ms, and write_limit_back raises completion from 39.0% to 100.0%.

Why direct VLA-to-controller dispatch fails in multi-arm cells

Connecting an LLM or VLA tool-call output directly to ROS 2 action servers and MoveIt 2 controllers exposes multi-arm workcells to four hardware failure modes. Even when gemini-4-carbon decomposes a multi-step task in the right logical order, single-shot coordinate prediction still produces targets outside the arm's spherical reach, end-effector boxes that clip workbench fixtures, wrist postures that exceed distal torque ratings under payload, and overlapping schedules where two arms enter the same shared zone at once.

Project STAMP (Spatial, Task & Motion Planning, v1.0.0-stamp) places a deterministic pre-dispatch gate between multimodal planning and controller execution through a four-stage Plan -> Gate -> Execute -> Write-Back loop. GeminiArgonPlanner emits only a declarative TaskDAG against a 3D scene snapshot (SpatialState). Neither DecoupledROS2Executor nor MoveItPreDispatchGuard can send a command to ROS 2 Jazzy until FrankaFR3DeterministicGate approves every node in the graph with GateVerdict.passed == True.

Project STAMP 4-Stage Closed-Loop Execution Pipeline (Plan -> Gate -> Execute -> Write-Back) Ref: M9G-TR-2026-03 (v1.0.0-stamp)
Stage 1 (Plan): GeminiArgonPlanner(Goal, SpatialState, RepairHistory) builds a candidate TaskDAG.
Stage 2 (Gate): FrankaFR3DeterministicGate(TaskDAG, SpatialState) checks four orthogonal physical layers in under 2 ms.
Stage 3 (Execute on PASS): DecoupledROS2Executor dispatches verified 7-DoF joint trajectories to ROS 2 Jazzy and MoveIt 2.
Stage 4 (Write-Back on REJECT): FeedbackContextStore.write_limit_back(HardwareFaultLog) appends exact repair bounds for the next planning turn.

Four Pydantic v2 schema contracts and video-to-TaskDAG grounding

stamp/stamp_schemas/ defines four Pydantic v2 models exported as strict JSON Schema Draft 2020-12 contracts via export_all_json_schemas() so the planner, the gate, and external MCP clients share one typed boundary:

  • TaskDAG & TaskNode (TaskDAG.schema.json): Encodes a parallel multi-arm task graph where each node declares node_id, assigned manipulator arm_id (FR3_1, FR3_2, FR3_3), skill action, world target_pose [x, y, z, yaw] in meters and radians, upstream dependencies, claimed shared_zone, required_tool, and scheduled time_window (t_start, t_end).
  • SpatialState (SpatialState.schema.json): Records the 3D workcell snapshot at planning time, including per-arm base frames and 7-DoF joint states (RobotArmState with joint_torques_nm and custom URDF joint_limits_rad), tracked 3D objects (ObjectPose3D), 3D obstacle AABBs (WorkspaceZoneBox), and active lock maps (active_zone_locks, active_tool_locks).
  • GateVerdict (GateVerdict.schema.json): Returned by FrankaFR3DeterministicGate.evaluate_dag() with boolean passed, approved_node_ids, rejected_node_ids, pre-solved 7-DoF IK joint angle arrays joint_solutions in radians, and cumulative interception_rate.
  • HardwareFaultLog & FaultCode (HardwareFaultLog.schema.json): Binds each rejected node_id and arm_id to a typed FaultCode, scalar measured_value and limit_value, physical unit, and a correction_hint string formatted via to_context_constraint().

Four orthogonal checks in FrankaFR3DeterministicGate and write_limit_back repair

FrankaFR3DeterministicGate._evaluate_single_node() runs four orthogonal physical checks on every candidate TaskNode, and MoveItPreDispatchGuard.verify_moveit_goal() enforces the same invariants at the controller boundary. If any node violates a check, the gate rejects the TaskDAG in under 2 ms and passes a structured HardwareFaultLog to FeedbackContextStore.write_limit_back():

Four Orthogonal Physical Checks (FrankaFR3DeterministicGate) Ref: M9G-TR-2026-03 • stamp/stamp_gate/__init__.py
1. Kinematic Reach & 7-DoF DLS IK: Target 3D radial distance from the assigned arm base must sit within 0.15 m to 0.85 m, and the 150-iteration Damped Least-Squares IK position residual must stay at or below 15.0 mm (0.015 m).
2. 3D Workspace & AABB Collision: Target height must stay at or above 0.20 m, radial clearance from the base column must be at least 0.12 m, and the gripper bounding box (±[0.04, 0.04, 0.05] m) must not intersect any obstacle box.
3. Joint Position & Torque Envelopes: All 7 FR3 joint angles must stay within URDF position bounds and joint torques must remain within [87, 87, 87, 87, 12, 12, 12] Nm.
4. Spatio-Temporal Mutex Locks: Any two task nodes on different arms that claim the same shared_zone or required_tool must hold strictly non-overlapping [t_start, t_end] execution windows.

FaultCode Enum Deterministic Trigger Condition Injected Context Constraint (write_limit_back) Planner Turn-2 Repair Transformation
IK_UNREACHABLE 3D radial distance outside [0.15 m, 0.85 m] from the assigned arm's fr3_link0 base, or 150-iteration 7-DoF DLS IK residual exceeds 15.0 mm. [STAMP_GATE_FAULT node=... arm=FR3_k code=IK_UNREACHABLE measured=1.98m limit=0.85m]: move target within 0.52m of base Projects target XY radially along the base-to-target ray onto the r = 0.52 m target radius and clamps Z within [0.32 m, 0.62 m].
WORKSPACE_COLLISION Target drops below table height (Z < 0.20m), enters the 0.12m base column cylinder, or end-effector AABB intersects an obstacle WorkspaceZoneBox. [STAMP_GATE_FAULT node=... code=WORKSPACE_COLLISION]: End-effector AABB intersects obstacle; raise Z above box.max_z + 0.08m Raises target Z to max(0.34m, box.max_z + 0.08m), or retracts XY to 0.5 × base_xyz at Z = 0.38m when vertical clearance exceeds 0.68m.
RESOURCE_CONTENTION Two manipulators claim the same shared_zone (such as central_table) or required_tool during overlapping [t_start, t_end] windows or an active lock. [STAMP_GATE_FAULT node=... code=RESOURCE_CONTENTION]: Shared zone contended over [0.00s, 1.50s]; shift time_window after 1.50s Shifts the contending node's time_window to [mutex_cursor + 0.15s, mutex_cursor + 0.15s + dur] and clears conflicting foreign locks.
JOINT_LIMIT_EXCEEDED Any of the 7 FR3 joint angles violates URDF [q_min, q_max] radians, or any joint torque exceeds [87, 87, 87, 87, 12, 12, 12] Nm. [STAMP_GATE_FAULT node=... code=JOINT_LIMIT_EXCEEDED measured=115.0Nm limit=87.0Nm]: retract moment arm & enable reduced_payload_mode Retracts target moment arm to 0.45 × base_xyz at Z = 0.38m, resets posture seed to FR3_HOME_CONFIG, and sets reduced_payload_mode = True.

Deploying StampStandaloneEngine over HTTP REST and MCP stdio

StampStandaloneEngine (stamp/api_server.py) runs the entire Plan -> Gate -> Write-Back loop outside the simulator as a zero-ROS-dependency service over HTTP REST on port :8095 or JSON-RPC 2.0 MCP stdio. External agent harnesses pass custom robot URDF XML definitions (parsed per request by parse_urdf_joint_limits()) and reach bounds on every call:

M9G-TR-2026-03 • StampStandaloneEngine REST & JSON-RPC 2.0 MCP Interface Author: Minsu Chang, Ph.D. (M9G)
MCP Tool / HTTP Endpoint Input Contract Deterministic Engine Behavior & Output
stamp_plan_and_verify
POST /v1/stamp/plan_and_verify		 goal, spatial_state, optional urdf_xml, reach_bounds_m, video_events, max_replans Loads custom URDF revolute and prismatic bounds, runs ClosedLoopStampOrchestrator.run_episode(), and returns the verified dag, verdict, and active_write_back_constraints.
stamp_verify_dag
POST /v1/stamp/verify_dag		 Candidate dag (TaskDAG), spatial_state, optional urdf_xml, reach_bounds_m Runs FrankaFR3DeterministicGate.evaluate_dag() in under 2 ms, appends any HardwareFaultLog entries to FeedbackContextStore, and returns GateVerdict with pre-solved 7-DoF joint_solutions.
stamp_write_limit_back
POST /v1/stamp/write_limit_back		 List of HardwareFaultLog objects from simulator or hardware protective stops Formats hardware faults into deduplicated [STAMP_GATE_FAULT ...] prompt constraints and returns updated fault_summary counts by FaultCode.

Combined with the batch runner (scripts/run_stamp_batch.py), the WSL2 FastDDS heartbeat watchdog (scripts/fastdds_watchdog.py), and the SHA-256 dataset freezer (scripts/freeze_stamp_bench_v1.py), Project STAMP gives multi-arm ROS 2 workcells a fast, reproducible safety boundary for frontier VLA planners.
